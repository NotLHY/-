## 2. 对 GPT 计划的判断

### 2.1 采纳（已写进第 3、4 节）

1. **诊断优先于继续扫参数**——逐类、子群、多图、复诊、置信度，先定位再动手。
2. **不用 test 做任何事**：不读标签、不按 test 分布加权、不用 test 选模。只在冻结后前向。
3. **逐类必须同时报阳性检查数与阳性患者数**，并给患者级区间；dev 的 class 1 只有 47 个阳性患者，±0.06 是常态。
4. **流程纪律**：在 dev 发现失败类型 → 回 train 找同类样本 → 改训练 → 在**未参与该次选择**的患者上确认；不把 dev 错题塞回训练再用 dev 分数宣称进步。

### 2.2 修正（附数字）

**（1）“训练取 2 张图、标签是检查级并集，可能监督不足”——方向对，量级要压。**

只有 **8.8%** 的训练检查有 ≥3 张图。而且标签是**检查级并集**：保留的每张图都拿同一个标签，所以不存在“漏标”，实际风险是**视图覆盖不足 + 潜在标签噪声**（阳性只在被丢弃的侧位上可见，却把正标签压在正位图上）。

上界是 8.8%，真实影响只会更小。先做 D2 统计（10 分钟、不烧卡），差距 ≥3 分才值得改结构。

**（2）“过拟合是当前瓶颈之一”——证据偏弱。**

第 6 轮 train 0.0530 / val 0.0582，**只差 0.005**；第 10 轮 val 升到 0.0726，是早停该拦下的正常现象，patience=4 已经拦住。真正要解释的是 **0.7972 → 0.7408** 这 5.6 分，那是**人群构成差**（复诊队列更难），不是训练集与验证集之间的过拟合。

所以“控过拟合”应排在第 3 位，不是第 1 位。

**（3）“80 分硬目标”——算术上仍不成立，建议改成 77 目标 / 79 冲刺。**

```
public ≈ 100 × valid(≥5) − 1.26
要 80 → valid(≥5) = 0.8126 → overall ≈ 0.855（现在 0.7972，差 +5.8）
要 77 → valid(≥5) = 0.7826 → overall ≈ 0.825（差 +2.8）
```

再叠加榜单噪声 1–2 分：**真值 79 的模型，单次提交可能显示 76 或 82**。把 80 当验收线可以，但当“必须达成”会在最后两天逼出无效操作。

### 2.3 补充（GPT 没看到的）

1. **98% 的配对是跨患者的**，患者内只占 2.2%（复诊子集 7.7%）。所以患者级平滑、患者级时序建模的天花板只有 +0.8/+2.6，且实测为负——**这条路可以正式关闭**，不要占用诊断预算。
2. **吞吐决定实验预算**：一轮 10–22 分钟，一个配置 2–4 小时，一天最多 3–4 个。GPT 的日历按“一天多个实验”排，实际要按“一天 1–2 个”排。
3. **valid 已经不是盲测**：`best.pt` 是按 official valid 的 macro-AUC 选的。所以后续必须写明：**选择看 dev，确认看 valid**，并承认 valid 被反复看过。

## 3. 诊断清单（先做，几乎不烧卡）

| 编号 | 问题 | 做法 | 产出 | 判据 |
|---|---|---|---|---|
| **D1** | 哪几类拖分最多 | `tools/report_valid.py`（valid）+ 解析 `evaluation_dev.json`（dev），合成 10 类 × 4 列（overall/≥5/≥10/dev） | 一张表 | 锁定 2–3 个主因类 |
| **D2** | 2 视图训练是否伤到 ≥3 图检查 | 在 dev 上对比「≥3 图检查」与「≤2 图检查」的逐类 AUC | 一张对比表 | 差距 ≥3 分才改 `max_train_views` |
| **D3** | 高置信错误是标签疑点还是困难病例 | dev 上取 P≥0.9 却判错的检查 + 24 个 run 的分歧样本，抽 20–30 例人工看 | 一份带图清单 | 能分成「标签疑点/困难/模型偏差」三类 |
| **D4** | 复诊次数是否越多人越难 | dev/valid 内按每人检查数分 5–6/7–9/10–14/15+ 四层算 AUC | 四层表 | 15+ 层若低 ≥4 分，说明长随访更难 |
| **D5** | 单图检查是否是主因 | dev 上单图 vs 多图 AUC（valid 上已知 0.730 vs 0.844；test 单图占 54.8%） | 两个数 | 单图显著更低 → 考虑视图 dropout |
| **D6** | 标签噪声上限 | 同一患者相邻检查的标签翻转率、同类共现率 | 每类一个翻转率 | 翻转率 >40% 的类，AUC 上限受标签限制 |

D1、D2、D4、D6 都可以在 CPU 上、用已有预测跑完；D3 需要人工看图；D5 已有部分结果。

## 6. 协议与合规

1. **角色分工**：`train` 训练；`dev`（200 复诊患者）做**选择**；`valid` 做**确认**并如实声明已被反复查看；`test` 只在冻结后前向。
2. **每个实验登记**（新建 `AI/docs/EXPERIMENTS.md`）：假设、配置 hash、dev/valid/逐类、判定、失败也留。
3. **配对比较**：同一 dev 上做患者聚类 bootstrap，报 Δ 与 95% CI，不只看点估计。
4. **合规红线**：test 图像不进训练/自监督/伪标签；不按 test 统计量加权；推理只前向。valid 并入终训只在所有选择冻结之后。
